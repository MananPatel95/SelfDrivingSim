# PR #39 — Left turn cheaper than U-turn plus a right; stack-faithful planning

## What changed

- `resolveTripDestination` sets `opposite` only when start and dest share a grid road **and** the click is left of that road's naive approach (`OPPOSITE_SIDE_LAT` −1.2 m). A cross-street dest that only needs a left / right / straight does not flip heading or insert `intersectionUTurn`.
- Cross-street pads call `slideOffIntersection(..., keepClickSide)` so a dest just past the corner stays on that arm. Same-street junction clicks still slide *backward* (park before the box).
- `beginTrip` / `reengageAutopilot` keep that first `ResolvedDestination` so a later re-resolve of the pad cannot flip a left into a U-turn+right.
- A legal left at an intersection stays near-Manhattan length — cheaper than going past, U-turning, and coming back for a right.
- Same-road opposite-side U-turn from [[pr-33]] is unchanged (`(0,22) → (−4.5,78)` still goes past the next junction).
- Live F1 / F2 / F3 planning is no longer one shared `planTrajectory` on one nav polyline. Tesla follows the nav route from camera detections; Waymo routes on the HD-map lane graph; Waabi scores occupancy-forecast candidates attracted to the dest route. Public-vs-approx notes: [[public-sources]].
- `Simulation.setPlannerStack` (F-keys, start menu, `?stack=`) rebuilds the current trip on the new style.
- Screenshot rigs: `?demo=left-near`, `?ab=sx,sy,ex,ey`, `?stack=tesla|waymo|waabi`.

## Why

The A→B map sometimes planned a dest one left away by going through the corner, U-turning, and returning for a right. #33 treated “left of the last Manhattan segment” as opposite even when that segment was a different street; sliding the pad backward then put the pin on the wrong arm. The standing goal is also that each view should plan the way the public stack description says, not only change HUD chrome.

## Public sources (not vendor code)

- **Tesla:** public FSD / AI Day — cameras only, E2E pixels→trajectory, nav route, no HD map. This PR approximates that with camera-FOV detections + pursuit of `mergeIntoLaneRoute`. No trained net.
- **Waymo:** public Waymo Driver / safety reports — HD lane-graph routing + multi-sensor fusion. This PR walks procedural HD driving lanes (`laneGraphRoute`). `connections[]` is empty, so hops are implicit crossings.
- **Waabi:** public blogs / papers — BEV occupancy, 1–3 s forecast, candidate scoring. This PR scores a fan + dest-route candidate against `predictFutureOccupancyFromAgents` (agent splat, not a learned predictor). `createBEVOccupancyFromAgents` is unchanged.
